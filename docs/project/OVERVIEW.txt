1. RINGKASAN PROYEK
--------------------------------------------------------------------------------
Nama Aplikasi : DompetKita
Tujuan        : Aplikasi manajemen dan pencatatan keuangan modern multi-akun
                (multi-tenant) untuk kebutuhan personal, rumah tangga (keluarga),
                maupun usaha kecil dengan fokus utama pada kecepatan loading,
                integritas saldo mutlak, dan pengalaman mobile yang mulus.
Tech Stack    : - Framework      : Laravel 13.x (PHP 8.2+)
                - UI Engine      : Filament PHP v5.x (Livewire v4)
                - Tenancy        : Filament Multi-Tenancy (Tenant Model: Account)
                - Mobile UI      : hammadzafar05/mobile-bottom-nav
                - Icon Picker    : guava/filament-icon-picker + mallardduck/blade-lucide-icons
                - Auth & 2FA     : Filament Breezy Plugin
                - AI Assistant   : Laravel Boost (https://laravel.com/framework/docs/boost)
                - Profiling/Dev  : fruitcake/laravel-debugbar (https://github.com/fruitcake/laravel-debugbar)
                - Database       : MySQL / PostgreSQL / SQLite


2. PRINSIP ARSITEKTUR UTAMA
--------------------------------------------------------------------------------
1. No Database Enum Types (Tanpa Tipe ENUM di Database):
   - Seluruh kolom status/tipe/kategori disimpan sebagai `string(20)` atau `string(30)`
     di level database untuk kompatibilitas penuh antar DBMS (MySQL, PostgreSQL, SQLite)
     dan kemudahan migrasi.
   - Integritas data dan validasi opsi dikelola sepenuhnya di level aplikasi
     menggunakan fitur resmi PHP 8.1+ Backed Enums (misal: `App\Enums\TransactionType`)
     dan Eloquent Model Attribute Casting (`$casts`).

2. Single-Currency per Tenant Architecture:
   - Setiap Akun Pembukuan (`Account`) menetapkan satu mata uang pelaporan (`currency_code`, default IDR),
     yang dipilih dari 154 mata uang unik global berbasis tabel master `countries`.
   - Seluruh dompet di bawah akun tersebut menggunakan mata uang yang sama. Pengelolaan aset
     valas dilakukan dengan membuat akun pembukuan terpisah guna menjaga akurasi 100% tanpa selisih kurs.

3. Pure Event Ledger (Buku Besar Mutasi Kas Riil):
   - Tabel `transactions` murni mencatat pergerakan kas riil (`amount`, `direction`, `happened_at`).
   - Saldo berjalan (running balance) dihitung secara dinamis via SQL Window Function saat laporan
     rekening koran dibuka. Pendekatan ini memungkinkan input transaksi mundur (backdated) dan
     edit/hapus secara aman tanpa merusak kebenaran data baris-baris historis lainnya.

4. Integritas Saldo Mutlak & Concurrency Guard:
   - Seluruh mutasi saldo dompet WAJIB dibungkus di dalam `DB::transaction()` dengan pessimistic
     locking (`lockForUpdate()`) untuk mencegah race condition (Lost Update) di MySQL & PostgreSQL.
   - Disediakan rutin rekonsiliasi bawaan (`php artisan wallet:reconcile`) sebagai mekanisme *self-healing*.

5. Performance-First & Fast Loading (Kecepatan Maksimal):
   - Database Indexing Optimal: Seluruh foreign key dan kolom pencarian/sorting
     (`account_id`, `happened_at`, `status`, `slug`, `order`) diberi indeks.
   - Composite Indexing untuk Tenancy: Menambahkan indeks gabungan seperti
     `(account_id, happened_at)` pada tabel mutasi untuk menjamin query riwayat
     tetap kilat meskipun data transaksi mencapai jutaan baris.
   - Denormalisasi Terkontrol: Kolom `account_id` dipasang langsung di tabel operasional
     (`budgets`, `transactions`, `transfers`, `debts`) untuk meniadakan query `JOIN`
     bertingkat saat scoping tenant di Filament.
   - Polymorphic Optimization: Menerapkan `Relation::enforceMorphMap` agar kolom polymorphic
     hanya menyimpan key pendek alih-alih FQCN class lengkap.
   - Profiling Ketat dengan Laravel Debugbar: Seluruh query, N+1 detection, memory
     usage, dan rendering timeline diaudit secara real-time selama development.
   - Filament Table Optimization: Menerapkan `deferLoading()` pada seluruh tabel,
     menghindari query N+1, dan membatasi ukuran paginasi default (15-20 data per halaman).

6. Mobile-First Experience (Optimal di Ponsel):
   - Memanfaatkan plugin `hammadzafar05/mobile-bottom-nav` yang menyediakan:
     * Bottom Navigation Bar responsif di perangkat mobile (< 1024px) untuk navigasi
       cepat yang mudah dijangkau ibu jari (*thumb-reach*).
     * Terintegrasi langsung dengan registry navigasi Filament, active state indicators,
       badge notifikasi, serta dukungan penuh tema dark mode.
     * Slide-over modal sebagai standar penginputan data agar alur pengguna tetap fokus.
   - Catatan Arsitektur: Package `hammadzafar05/filament-mobile-preset` TIDAK digunakan
     karena memiliki inkompatibilitas fundamental dengan Livewire SPA Mode (`->spa()`).
     Preset tersebut menginjeksi tag `<style data-navigate-track>` pada render hook
     `HEAD_END` dan override layout yang membekukan lifecycle navigasi Livewire
     (progress bar macet, re-hydration Alpine terhenti, dark mode hilang, dan konten blank).
     Penggunaan `hammadzafar05/mobile-bottom-nav` secara mandiri terbukti 100% stabil,
     ringan, dan mulus saat navigasi SPA aktif.

7. AI-Assisted Architecture & Standards (Laravel Boost):
   - Terintegrasi dengan Laravel Boost (`https://laravel.com/framework/docs/boost`)
     sebagai MCP server resmi untuk memandu AI coding agents dalam memahami skema DB,
     routes, best practices Laravel 13, dan konvensi proyek yang tersimpan di `.ai/rules`.

8. Konvensi Urutan Kolom Migrasi Database (Column Ordering Standard):
   - Setiap kali membuat atau mendefinisikan tabel baru dalam migrasi (`Schema::create`),
     urutan penulisan kolom WAJIB mengikuti tata urutan baku berikut:
     1. id               : Primary key (`$table->id();`)
     2. timestamps       : Waktu pembuatan & pembaruan sistem (`$table->timestamps();`)
     3. softDeletes      : Waktu penghapusan lunak (`$table->softDeletes();`, jika tabel mendukung soft delete)
     4. Waktu / Temporal : Semua kolom yang berhubungan dengan waktu kejadian/transaksi/status
                           (misal: `happened_at`, `invited_at`, `confirmed_at`, `left_at`, `revoked_at`,
                           `due_date`, `paid_at`, `period_start`, `period_end`, dll.)
     5. Lainnya          : Foreign keys, string nama/kode, angka nominal, teks catatan, status, boolean, dll.
   - Konvensi ini memastikan struktur fisik skema konsisten, rapi, dan seragam di seluruh aplikasi.


3. ARSITEKTUR MULTI-TENANCY & HAK AKSES
--------------------------------------------------------------------------------
- Tenant Utama: `Account` (Akun Pembukuan, route key: `slug`).
  Satu user dapat memiliki banyak akun (misal: "Keuangan Pribadi", "Keuangan Rumah Tangga").
- Manajemen Anggota: `account_member`.
  * Tabel pivot `account_member` menjadi satu-satunya sumber relasi keanggotaan.
  * Saat user membuat akun, ia otomatis didaftarkan ke `account_member` dengan role `'owner'`
    dan status `'active'`.
  * Relasi Filament `HasTenants` (`$user->accounts()`) secara ketat memfilter hanya akun
    dengan `status = 'active'`.
  * Hak akses operasional dikendalikan oleh Laravel Policy per-resource:
    - `owner`  : Hak penuh (CRUD operasional, kelola member, hapus akun).
    - `member` : Hak operasional penuh (CRUD transaksi, dompet, kategori, anggaran, hutang).
    - `viewer` : Read-only (hanya memantau dashboard, tabel, dan laporan).

- Proteksi Rute Tenant & Intended URL Sanitizer (`ValidateTenantAccess` Middleware):
  * Masalah yang diatasi:
    Ketika database di-reset (`php artisan migrate:fresh --seed`) saat pengguna masih membuka
    halaman rute tenant tertentu (misal: `/app/keuangan-pribadi/categories`), sesi login terputus.
    Jika tidak dicegah, middleware otentikasi bawaan akan menyimpan URL rute tenant lama yang belum/tidak
    ada di DB ke dalam session `url.intended`. Setelah login berhasil, pengguna diredirect ke intended URL
    tersebut dan mengalami `404 Not Found` (karena route model binding `{tenant:slug}` gagal menemukan entitas `Account`).
  * Solusi Terintegrasi:
    1. Middleware `ValidateTenantAccess` dipasang pada panel Filament dan diprioritaskan sebelum
       `AuthenticatesRequests` via `$middleware->prependToPriorityList(...)` di `bootstrap/app.php`.
    2. Jika pengguna belum login (guest) mengakses rute tenant yang tidak ada di DB:
       Middleware otomatis membersihkan session `url.intended` dan me-redirect langsung ke `/app/login`.
       Dengan demikian, setelah login, pengguna tidak dilempar ke intended URL 404, melainkan langsung diarahkan
       ke default tenant miliknya atau ke `/app/new`.
    3. Jika pengguna terotentikasi mengakses slug tenant yang tidak ada di DB:
       Middleware me-redirect pengguna secara aman ke default tenant yang ia miliki (`$user->getDefaultTenant()`),
       atau ke `/app/new` jika belum memiliki akun sama sekali.
    4. Sanitasi Otomatis: Setiap request membersihkan session `url.intended` jika merujuk ke slug tenant non-aktif/non-eksisten.
    5. Exception Handler Fallback: Menangani `ModelNotFoundException` pada `Account` di `bootstrap/app.php`
       sebagai jaring pengaman tambahan jika binding model gagal di level router.
    6. Default Seed: `AccountSeeder` diikutsertakan dalam `DatabaseSeeder` sehingga setelah `php artisan migrate:fresh --seed`,
       akun default `keuangan-pribadi` milik `admin@email.com` otomatis tersedia lengkap dengan 4 kategori sistem
       dan 1 dompet default ("Dompet Utama").


4. SPESIFIKASI SKEMA DATABASE (NO DB ENUMS)
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
A. CORE & OTENTIKASI
--------------------------------------------------------------------------------

1. users (Bawaan Laravel + Breezy)
   - id                  : id (primary key)
   - timestamps
   - email_verified_at   : timestamp (nullable)
   - name                : string
   - email               : string (unique)
   - password            : string
   - two_factor_secret   : text (nullable, Breezy 2FA)
   - two_factor_recovery : text (nullable, Breezy 2FA)
   - avatar_url          : string(500), nullable
   - remember_token      : string (nullable)

2. accounts (Tabel Tenant / Pembukuan)
   Deskripsi: Mencatat entitas pembukuan independen.
   - id            : id (primary key)
   - timestamps
   - softDeletes
   - owner_id      : foreignId -> users.id (cascade on delete)
   - name          : string, index
   - slug          : string, index (digunakan sebagai route tenant key, unik per owner_id: unique(['owner_id', 'slug']))
   - currency_code : string(3), default('IDR') (mata uang pelaporan akun)
   - description   : text, nullable
   - Catatan Tenancy: Unik per owner_id memungkinkan pengguna berbeda memiliki akun bernama sama
     (misal: 'keuangan-pribadi') tanpa tabrakan. Resolusi tenant memprioritaskan akun milik/dikelola
     oleh pengguna yang sedang login ($user->accounts()->where('accounts.slug', $slug)).

3. account_member (Tabel Pivot & Undangan Member Tenant)
   Deskripsi: Menghubungkan user ke akun beserta status dan hak aksesnya.
   - id               : id (primary key)
   - timestamps
   - invited_at       : timestamp, nullable, index
   - confirmed_at     : timestamp, nullable, index
   - left_at          : timestamp, nullable, index
   - revoked_at       : timestamp, nullable, index
   - account_id       : foreignId -> accounts.id (cascade on delete)
   - user_id          : foreignId -> users.id, nullable (diisi saat user sudah terdaftar/klaim)
   - email            : string, index (email tujuan undangan)
   - invitation_token : string(64), nullable, unique (token untuk klaim undangan)
   - role             : string(20), default('member'), index
                        (pilihan via PHP Enum: owner, member, viewer)
   - status           : string(20), default('invited'), index
                        (pilihan via PHP Enum: invited, active, left, revoked)
   - Constraint       : unique(account_id, email)

4. countries (Master Data Negara & Mata Uang)
   Deskripsi: Tabel referensi 250 negara dan 154 mata uang unik dunia untuk pilihan mata uang akun pembukuan.
   - id              : id (primary key)
   - timestamps
   - name            : string, index (contoh: "Indonesia", "United States")
   - iso2            : string(2), unique (contoh: "ID", "US")
   - iso3            : string(3), unique (contoh: "IDN", "USA")
   - numeric_code    : string(10), nullable
   - phonecode       : string(20), nullable
   - capital         : string, nullable
   - currency        : string(10), index (kode mata uang ISO 4217, contoh: "IDR", "USD")
   - currency_name   : string, index (contoh: "Indonesian rupiah")
   - currency_symbol : string(20), nullable (contoh: "Rp", "$")
   - region          : string, nullable, index
   - subregion       : string, nullable, index
   - nationality     : string, nullable, index
   - latitude        : decimal(10, 8), nullable
   - longitude       : decimal(11, 8), nullable

--------------------------------------------------------------------------------
B. MASTER DATA KEUANGAN
--------------------------------------------------------------------------------

5. wallets (Dompet / Akun Kas)
   Deskripsi: Tempat penyimpanan saldo uang fisik maupun digital (Bank, E-Wallet, Kas Tunai).
   - id              : id (primary key)
   - timestamps
   - softDeletes
   - account_id      : foreignId -> accounts.id (cascade on delete)
   - name            : string, index (contoh: "Bank UOB", "BCA", "Dompet Tunai")
   - slug            : string, index
   - icon            : string(100), nullable (diinput via guava/filament-icon-picker, trigger box height 5.75rem proporsional)
   - color           : string(50), nullable (diinput via ColorPicker)
   - current_balance : decimal(24, 2), default(0.00), index
                       (saldo riil saat ini, dikelola otomatis via DB Transaction + lockForUpdate)
                       (pada tabel diformat otomatis sesuai mata uang tenant: misal IDR -> "Rp 150.000", USD -> "$150.00")
   - allow_minus     : boolean, default(false), index (apakah saldo boleh bernilai minus)
   - Saldo Awal      : Saat dompet dibuat dengan saldo awal > 0, sistem otomatis mencatat
                       transaksi pemasukan awal dengan kategori sistem SYSTEM_INITIAL_BALANCE.
   - Indexing        : index(account_id, slug), index(account_id, current_balance)
   - Validasi Unik   : Ditegakkan di level aplikasi via Rule::unique('wallets', 'name')->where('account_id', $accountId)->whereNull('deleted_at')

6. categories (Kategori Pemasukan & Pengeluaran)
   Deskripsi: Klasifikasi transaksi keuangan per akun.
   - id         : id (primary key)
   - timestamps
   - softDeletes
   - account_id : foreignId -> accounts.id (cascade on delete)
   - name       : string, index (contoh: "Gaji", "Makanan & Minuman", "Listrik")
   - slug       : string, index
   - type       : string(20), index
                  (pilihan via PHP Enum: income, expense)
   - is_system  : boolean, default(false), index (kategori bawaan sistem/template)
   - icon       : string(100), nullable, index (diinput via guava/filament-icon-picker, posisi paling atas form dan full-width)
   - color      : string(50), nullable, index
   - order      : unsignedInteger, default(0), index (urutan sorting tampilan, diatur langsung via drag-and-drop reorder di tabel)
   - status     : string(20), default('active'), index
                  (pilihan via PHP Enum: active, inactive)
   - Kategori Sistem Default:
     * SYSTEM_INITIAL_BALANCE (Type: income, Icon: heroicon-o-sparkles, Color: success, Order: 1)
     * SYSTEM_TRANSFER_IN     (Type: income, Icon: heroicon-o-arrow-down-left, Color: success, Order: 2)
     * SYSTEM_TRANSFER_OUT    (Type: expense, Icon: heroicon-o-arrow-up-right, Color: danger, Order: 3)
     * SYSTEM_TRANSFER_FEE    (Type: expense, Icon: heroicon-o-banknotes, Color: warning, Order: 4)
     * Catatan: Kategori sistem disembunyikan dari tabel manajemen kategori (where is_system = false).
   - Indexing   : index(account_id, type), index(account_id, slug)
   - Validasi Unik: Ditegakkan di level aplikasi via Rule::unique('categories', 'name')->where('account_id', $accountId)->whereNull('deleted_at')

--------------------------------------------------------------------------------
C. TRANSAKSI & MUTASI
--------------------------------------------------------------------------------

7. transactions (Buku Besar / Ledger Mutasi Kas)
   Deskripsi: Buku besar seluruh pergerakan uang masuk dan keluar riil.
   - id            : id (primary key)
   - timestamps
   - softDeletes
   - happened_at   : timestamp, index (waktu transaksi riil terjadi)
   - account_id    : foreignId -> accounts.id (cascade on delete)
   - wallet_id     : foreignId -> wallets.id (cascade on delete)
   - category_id   : foreignId -> categories.id, nullable (null on delete)
   - transfer_id   : unsignedBigInteger, nullable, index (fk ke transfers di Milestone 3)
   - type          : string(20), default('transaction'), index
                     (pilihan via PHP Enum: transaction, transfer)
   - direction     : smallInteger [1: Pemasukan, -1: Pengeluaran], index
   - amount        : decimal(24, 2), index (nominal transaksi, selalu positif)
   - category_name : string(255), nullable (arsip denormalisasi untuk kecepatan history)
   - wallet_name   : string(255) (arsip denormalisasi nama dompet)
   - note          : text, nullable
   - Performance Index: index(account_id, happened_at), index(wallet_id, happened_at)
   - Sort Order Baku  : happened_at DESC, id DESC

8. transfers (Transfer Antar Dompet)
   Deskripsi: Header pemindahan dana antar dompet (Double-Entry Bookkeeping).
   - id                  : id (primary key)
   - timestamps
   - happened_at         : timestamp, index
   - account_id          : foreignId -> accounts.id (cascade on delete)
   - from_wallet_id      : foreignId -> wallets.id (restrict on delete)
   - to_wallet_id        : foreignId -> wallets.id (restrict on delete)
   - from_transaction_id : foreignId -> transactions.id, nullable
   - to_transaction_id   : foreignId -> transactions.id, nullable
   - fee_transaction_id  : foreignId -> transactions.id, nullable
   - amount              : decimal(24, 2), index (nominal dana yang dipindahkan)
   - fee_amount          : decimal(24, 2), default(0.00), index (nominal biaya transfer)
   - note                : text, nullable
   - Performance Index   : index(account_id, happened_at)

--------------------------------------------------------------------------------
D. ANGGARAN (BUDGETING)
--------------------------------------------------------------------------------

9. budgets (Batas Pengeluaran Kategori)
   Deskripsi: Perencanaan alokasi pengeluaran per kategori per periode.
   - id               : id (primary key)
   - timestamps
   - period_start     : timestamp, nullable
   - period_end       : timestamp, nullable
   - account_id       : foreignId -> accounts.id (cascade on delete)
   - category_id      : foreignId -> categories.id (cascade on delete)
   - max_amount       : decimal(24, 2), index (batas plafon anggaran, tidak boleh minus)
   - alert_percentage : unsignedSmallInteger, default(80)
                        (persentase peringatan dashboard saat pengeluaran mendekati plafon)
   - period_type      : string(20), index
                        (pilihan via PHP Enum: monthly, custom)
   - year             : unsignedSmallInteger, nullable (untuk periode bulanan)
   - month            : unsignedTinyInteger, nullable (untuk periode bulanan)
   - Constraint       : unique(category_id, year, month)
   - Performance Index: index(account_id, period_start, period_end)

--------------------------------------------------------------------------------
E. HUTANG & PIUTANG (DEBTS)
--------------------------------------------------------------------------------

10. debts (Pencatatan Pinjaman & Piutang)
    Deskripsi: Mencatat pinjaman yang harus dibayar (payable) atau piutang yang harus ditagih (receivable).
    - id                     : id (primary key)
    - timestamps
    - softDeletes
    - due_date               : timestamp, nullable, index (tenggat waktu jatuh tempo)
    - account_id             : foreignId -> accounts.id (cascade on delete)
    - wallet_id              : foreignId -> wallets.id (restrict on delete)
    - initial_transaction_id : foreignId -> transactions.id, nullable
                               (transaksi otomatis di dompet saat hutang/piutang pertama dibuat)
    - counterparty_name      : string(255), index (nama orang/lembaga yang berpiutang/berhutang)
    - type                   : string(20), index
                               (pilihan via PHP Enum: payable, receivable)
                               - payable    : Kita berhutang (kewajiban bayar)
                               - receivable : Orang lain berhutang ke kita (hak tagih)
    - initial_amount         : decimal(24, 2), index (nominal pokok pinjaman/piutang)
    - paid_amount            : decimal(24, 2), default(0.00), index (total yang telah dilunasi)
    - note                   : text, nullable
    - Performance Index      : index(account_id, type)

11. debt_payments (Pembayaran Cicilan / Pelunasan Hutang-Piutang)
    Deskripsi: Riwayat pembayaran berkala yang memotong sisa hutang/piutang.
    - id             : id (primary key)
    - timestamps
    - paid_at        : timestamp, index
    - debt_id        : foreignId -> debts.id (cascade on delete)
    - transaction_id : foreignId -> transactions.id (restrict on delete)
    - amount         : decimal(24, 2), default(0.00) (nominal yang dibayarkan)

--------------------------------------------------------------------------------
F. PENDUKUNG (ATTACHMENTS)
--------------------------------------------------------------------------------

12. attachments (Lampiran File Polymorphic)
    Deskripsi: Menyimpan berkas bukti transfer, nota, struk, atau dokumen terkait.
    - id              : id (primary key)
    - timestamps
    - softDeletes
    - attachable_type : string(100), index (menggunakan Relation::enforceMorphMap)
    - attachable_id   : unsignedBigInteger, index
    - file_path       : string(500) (lokasi file di storage)
    - mime_type       : string(100), index
    - size            : unsignedBigInteger, index (ukuran berkas dalam bytes)
    - Performance Index: index(attachable_type, attachable_id)


5. PANDUAN ANTARMUKA PENGGUNA & ALUR (UI / UX FLOW)
--------------------------------------------------------------------------------

A. HEADER, TOPBAR & TENANT SWITCHER
--------------------------------------------------------------------------------
1. Pemilihan Akun (Tenant Switcher Dropdown):
   - Terletak di kiri atas panel/sidebar, menampilkan avatar akun dan nama akun aktif
     saat ini (contoh: "Keuangan Pribadi").
   - Ketika diklik, menampilkan dropdown menu:
     * Daftar Akun: Menampilkan daftar seluruh akun milik user (`owned`) dan akun
       tempat user terdaftar sebagai anggota aktif (`member`). User dapat berganti konteks
       pembukuan dengan 1 kali klik tanpa logout.
     * Daftarkan Akun Baru (`RegisterAccount`): Membuka form untuk membuat akun
       pembukuan baru (misal: "Keuangan Rumah Tangga").
     * Info & Anggota Akun (`EditTenantProfile`): Membuka modal pengaturan akun:
       - Mengubah nama akun, deskripsi, dan mata uang acuan (`currency_code`).
       - Tab / Seksi "Kelola Anggota": Menampilkan tabel member aktif dan tombol
         "Undang Anggota" (memasukkan email & role: member/viewer).
2. Notifikasi Database (Ikon Lonceng):
   - Menampilkan notifikasi peringatan anggaran yang menipis/melebihi batas,
     serta pemberitahuan undangan akun baru.
3. User Profile Dropdown (Filament Breezy):
   - Terletak di kanan atas (atau bagian bawah sidebar):
     * Profil Saya: Mengubah nama, email, dan foto avatar.
     * Keamanan Akun: Ubah kata sandi dan pengaturan Two-Factor Authentication (2FA).
     * Keluar (Logout).

B. MENU SIDEBAR (DESKTOP) & BOTTOM NAV (MOBILE)
--------------------------------------------------------------------------------

1. Dasbor (Dashboard)
   - Widget Statistik Ringkasan (Stats Overview):
     * Total Saldo Kas: Akumulasi saldo seluruh dompet aktif dalam format mata uang (Rp).
     * Total Pemasukan Bulan Ini: Badge hijau dengan filter opsional sertakan/kecualikan transfer.
     * Total Pengeluaran Bulan Ini: Badge merah dengan filter opsional sertakan/kecualikan transfer.
     * Total Sisa Hutang & Piutang: Ringkasan total kewajiban bayar dan hak tagih aktif.
   - Widget Grafik Finansial (ApexCharts):
     * Grafik Arus Kas (TransactionChart): Perbandingan bar/area chart pemasukan vs pengeluaran
       dalam 30 hari terakhir.
     * Grafik Kategori Pengeluaran (CategoryChart): Donut chart alokasi pengeluaran
       terbanyak bulan ini.
   - Peringatan Anggaran (Budget Alert Banner):
     * Banner/Callout dinamis yang muncul otomatis jika ada kategori belanja yang
       pengeluarannya telah mencapai persentase alert (misal: >= 80%).
   - Transaksi Terakhir (Latest Transactions Table):
     * Menampilkan 5 transaksi mutasi terakhir dengan tombol cepat (shortcut) untuk melihat/mengedit.

2. Dompet (Wallets)
   - Label Model & Navigasi: "Dompet"
   - Tampilan Tabel:
     * Kolom:
       - icon   : Ikon dompet (warna ikon mengikuti nilai kolom `color`).
       - nama   : Nama dompet (warna tulisan mengikuti nilai kolom `color`).
       - saldo  : Saldo saat ini (`current_balance` diformat mata uang akun).
       - minus  : Ikon boolean boleh saldo negatif (`allow_minus`).
     * Filter Tong Sampah (*TrashedFilter*) untuk melihat dan memulihkan dompet terhapus.
   - Aksi Tiap Baris:
     * Ubah (Membuka Slide-Over Modal).
     * Hapus (Soft Delete ke tong sampah).
     * Pulihkan / Hapus Permanen (jika berada di filter Tong Sampah).
   - Form Tambah / Ubah Dompet (Slide-Over Modal):
     * Icon (IconPicker via `guava/filament-icon-picker`, label: "Icon").
     * Nama Dompet (label: "Nama Dompet", validasi scopedUnique per tenant).
     * Saldo Awal (label: "Saldo Awal", hanya tampil saat create, numeric default 0;
       jika diisi > 0 otomatis mencatat transaksi `SYSTEM_INITIAL_BALANCE`).
     * Warna (ColorPicker, label: "Warna").
     * Bolehkan Saldo Negatif (Toggle, label: "Bolehkan Saldo Negatif").

3. Kategori (Categories)
   - Kategori Sistem:
     * Kategori bawaan sistem (`SYSTEM_INITIAL_BALANCE`, `SYSTEM_TRANSFER_IN`,
       `SYSTEM_TRANSFER_OUT`, `SYSTEM_TRANSFER_FEE`) TIDAK ditampilkan di tabel list.
   - Tampilan Tabel:
     * Reorderable: Pengurutan posisi kategori langsung via drag-and-drop di tabel (`$table->reorderable('order')->defaultSort('order', 'asc')`).
     * Kolom:
       - icon   : Ikon kategori (warna ikon mengikuti nilai kolom `color`).
       - nama   : Nama kategori.
       - status : Status kategori (Badge: Aktif / Nonaktif).
   - Filter: Tipe (Pemasukan/Pengeluaran), Status (Aktif/Nonaktif), Tong Sampah.
   - Form Tambah / Ubah Kategori (Slide-Over Modal):
     * Icon: Label "Icon" (IconPicker via `guava/filament-icon-picker`, diletakkan paling atas, `columnSpanFull()`).
     * Tipe Transaksi: Radio Pemasukan (Income) atau Pengeluaran (Expense).
     * Nama Kategori: Label "Nama Kategori", validasi scopedUnique per tenant.
     * Warna: Label "Warna" (ColorPicker).
     * Status: Label "Status" (Select Aktif / Nonaktif).
     * (Catatan: Input "Urutan" ditiadakan dari form karena diatur langsung dari tabel).

4. Transaksi (Transactions & Transfers)
   - Tampilan Tabel Mutasi:
     * Tanggal & Waktu (`happened_at`), Tipe Mutasi (Badge: Pemasukan / Pengeluaran / Transfer),
       Nominal (format mata uang hijau/merah), Dompet Terkait, Kategori (kategori sistem untuk transfer),
       Catatan, Bukti Struk/Lampiran.
   - Filter Lengkap:
     * Rentang Tanggal (Date Range Picker), Dompet, Kategori, Tipe Mutasi.
   - Tombol Aksi Header:
     * "Catat Transaksi" (Pemasukan/Pengeluaran biasa).
     * "Transfer Antar Dompet" (Pemindahan dana).
   - Form Transaksi Biasa (Slide-Over Modal):
     * Pilihan Tipe: Pemasukan atau Pengeluaran.
     * Dompet Terpilih.
     * Kategori Terpilih (difilter sesuai tipe Income/Expense).
     * Nominal Transaksi (Numeric field dengan format mata uang).
     * Tanggal & Waktu Transaksi (default: saat ini).
     * Catatan / Deskripsi.
     * Upload Foto Struk/Nota (`attachments`).
   - Form Transfer Antar Dompet (Slide-Over Modal):
     * Dompet Asal (`from_wallet_id`).
     * Dompet Tujuan (`to_wallet_id`, otomatis dicegah memilih dompet yang sama).
     * Nominal Dana yang Ditransfer.
     * Biaya Admin / Fee (opsional, memotong dompet asal).
     * Tanggal & Waktu Transfer.
     * Catatan & Bukti Transfer.

5. Anggaran (Budgets)
   - Tampilan Tabel:
     * Kategori Belanja, Periode (Bulanan: Bulan & Tahun / Custom), Plafon Anggaran,
       Pengeluaran Terpakai, Progress Bar Visual dengan indikator warna (Hijau aman,
       Kuning waspada, Merah overbudget).
   - Form Anggaran (Slide-Over Modal):
     * Kategori Belanja (hanya kategori bertipe Expense).
     * Plafon Anggaran (`max_amount`).
     * Tipe Periode: Bulanan (Pilih Bulan & Tahun) atau Custom (Rentang Tanggal).
     * Persentase Alert (`alert_percentage`, default: 80%).

6. Hutang & Piutang (Debts)
   - Tampilan Tabel:
     * Nama Orang/Lembaga, Tipe (Badge Merah: Hutang / Badge Hijau: Piutang),
       Nominal Pokok, Total Terbayar, Sisa Hutang/Piutang, Jatuh Tempo, Progress Pelunasan.
   - Aksi Tiap Baris:
     * "Bayar / Terima Cicilan": Membuka modal pembayaran cepat (`debt_payments`).
     * Ubah / Hapus.
   - Form Catat Hutang/Piutang Baru (Slide-Over Modal):
     * Nama Pihak Terkait (*Counterparty*).
     * Tipe: Hutang (*Payable*) atau Piutang (*Receivable*).
     * Dompet Terkait:
       - Jika Hutang: Dompet penerima pencairan uang (saldo kas otomatis bertambah).
       - Jika Piutang: Dompet sumber pinjaman (saldo kas otomatis berkurang).
     * Nominal Pokok Pinjaman.
     * Tanggal Jatuh Tempo (*Due Date*).
     * Catatan / Perjanjian.
   - Form Pembayaran Cicilan / Pelunasan (Modal Action):
     * Dompet Pembayaran (kas keluar jika bayar hutang, kas masuk jika terima piutang).
     * Nominal Pembayaran.
     * Tanggal Bayar.
     * Catatan & Upload Bukti Pembayaran.

6. ATURAN BISNIS & ALUR FINANSIAL (CORE RULES)
--------------------------------------------------------------------------------
1. Integritas Saldo Dompet (ACID Transaction & Concurrency Guard):
   - Seluruh mutasi saldo dompet WAJIB dibungkus di dalam `DB::transaction()` dengan pessimistic
     lock: `$wallet = Wallet::where('id', $walletId)->lockForUpdate()->first();`.
   - Formula Update:
     `new_balance = current_balance + (direction * amount)`
   - Cek batas saldo minus: Jika `new_balance < 0` dan `allow_minus = false`, lemparkan exception.

2. Alur Reversal Transaksi (Edit & Delete):
   - Saat Transaksi Dihapus:
     `wallet->current_balance -= (direction * amount)` (pembalikan saldo).
   - Saat Transaksi Diubah (Nominal atau Dompet Berubah):
     * Saldo lama dikembalikan ke dompet lama.
     * Saldo baru diterapkan ke dompet baru.
     * Seluruh proses dieksekusi dalam satu transaksi DB terkunci.

3. Alur Transfer Antar Dompet:
   - Mengunci kedua dompet secara berurutan berdasarkan ID (`orderBy('id')`) untuk mencegah deadlocks.
   - Transfer menghasilkan 1 row di tabel `transfers` dan minimal 2 row di `transactions`:
     * Dari Dompet Asal : `direction: -1`, `type: 'transfer'`, `transfer_id: $transfer->id`,
       `category_id: $sysCatTransferOut->id`.
     * Ke Dompet Tujuan : `direction: 1`,  `type: 'transfer'`, `transfer_id: $transfer->id`,
       `category_id: $sysCatTransferIn->id`.
     * Biaya Admin (jika ada): 1 row transaksi pengeluaran tambahan pada dompet asal (`direction: -1`),
       `category_id: $sysCatTransferFee->id`.
   - Di dashboard/laporan statistik, user memiliki toggle filter untuk menyertakan atau mengecualikan
     transaksi bertipe `transfer` dari perhitungan pengeluaran/pemasukan operasional.

4. Alur Pencatatan Hutang & Piutang:
   - Saat membuat Hutang (Payable):
     * User wajib memilih dompet kas penerima.
     * Saldo dompet penerima otomatis bertambah (`direction: 1`).
     * `initial_transaction_id` otomatis terisi menautkan transaksi kas tersebut.
   - Saat membuat Piutang (Receivable):
     * User wajib memilih dompet kas sumber.
     * Saldo dompet sumber otomatis berkurang (`direction: -1`).
     * `initial_transaction_id` otomatis terisi menautkan transaksi kas tersebut.
   - Pembayaran cicilan (`debt_payments`):
     * Memotong saldo pokok hutang (`paid_amount += payment.amount`).
     * Menghasilkan transaksi dompet sesuai aliran dana (bayar hutang = uang keluar, terima piutang = uang masuk).

5. Alur Multi-Tenancy & Undangan Member:
   - Tenant Model adalah `Account`.
   - Menggunakan relasi `HasTenants` bawaan Filament v5.
   - Saat user membuat akun, ia otomatis di-insert ke pivot `account_member` dengan `role = 'owner'`
     dan `status = 'active'`.
   - Jika calon anggota diundang via email:
     * Dibuat record di `account_member` dengan status `'invited'` dan `invitation_token`.
     * Tautan `/invitations/{token}` memandu user baru mendaftar dengan email terkunci, atau
       memandu user yang sudah login untuk menerima undangan dalam satu klik konfirmasi.
     * Setelah terkonfirmasi, status berubah menjadi `'active'` dan user langsung dapat mengakses akun.


7. PEDOMAN OPTIMISASI PERFORMA & LOADING (HIGH SPEED GUIDELINES)
--------------------------------------------------------------------------------
1. Polymorphic Optimization:
   - Terapkan `Relation::enforceMorphMap` di `AppServiceProvider`:
     `'transaction' => Transaction::class`, `'debt' => Debt::class`.
   - Menghemat ukuran indeks DB dan mempercepat join polymorphic.

2. Profiling & Eliminasi N+1 (Laravel Debugbar):
   - Pasang package `fruitcake/laravel-debugbar` untuk environment lokal:
     `composer require fruitcake/laravel-debugbar --dev`
   - Memonitor jumlah query SQL, execution time, dan memory footprint di setiap
     halaman panel untuk memastikan 0 N+1 query sebelum kode dirilis ke production.

3. Filament UI & Data Loading:
   - Gunakan `->deferLoading()` pada semua Table Resource agar halaman terbuka instan
     dan data dimuat secara asynchronously tanpa memblokir first-contentful-paint (FCP).
   - Tetapkan batas paginasi default yang efisien: `->defaultPaginationPageOption(15)`.
   - Hindari pemanggilan relasi N+1 di table column (gunakan `$record->wallet_name`
     dari arsip denormalisasi atau eager loading resmi via `modifyQueryUsing(fn ($q) => $q->with(...))`).

4. Query & Composite Indexing:
   - Manfaatkan indeks komposit `(account_id, happened_at)` pada `transactions`
     agar filter widget dashboard rentang tanggal bulanan/tahunan dieksekusi
     dalam hitungan milidetik tanpa full-table scan.
   - Gunakan agregasi SQL murni (`selectRaw('SUM(...)')`) saat menghitung ringkasan
     total balance dan cashflow daripada memanggil `.sum()` pada koleksi model Eloquent.

5. Mobile & Frontend Assets:
   - Plugin `hammadzafar05/mobile-bottom-nav` mengoptimalkan navigasi mobile dengan
     konsumsi resource minimal dan kompatibilitas penuh dengan Filament SPA mode.
   - Aktifkan route caching, config caching, view caching, dan icon caching pada server production:
     `php artisan optimize`
     `php artisan icons:cache`
   - Pastikan PHP OPcache aktif pada server PHP 8.2+.


8. ROADMAP MILESTONE IMPLEMENTASI
--------------------------------------------------------------------------------
Pengembangan DompetKita dibagi menjadi 6 Milestone berurutan dan terisolasi
untuk menjamin kestabilan arsitektur, kepatuhan TDD, dan pencegahan regresi:

- Milestone 1: Multi-Tenancy Foundation
  * Fokus: Fondasi tenant Filament v5, model Account, pivot account_member.
  * Deliverables:
    - PHP 8.4 Backed Enums: AccountRole (Owner, Member, Viewer) & MemberStatus
      (Invited, Active, Left, Revoked) mengimplementasikan HasLabel & HasColor.
    - Migrasi accounts dan account_member + AccountFactory.
    - Model Account (slug generator, relasi owner & members) dan User
      (kontrak HasTenants, HasDefaultTenant, canAccessTenant).
    - Halaman registrasi tenant Filament v5 RegisterAccount (RegisterTenant).
    - Konfigurasi AppPanelProvider dengan tenant slug (/app/{slug}).
    - Pest Feature Tests: Isolasi tenant, penolakan akses lintas tenant, dan redirect.

- Milestone 2: Core Master Data (Wallets & Categories)
  * Fokus: Pengelolaan rekening kas/dompet dan kategori transaksi beranggaran.
  * Deliverables:
    - Migrasi wallets dan categories + factories & seeders.
    - Seeder Kategori Default Sistem (Biaya Admin Transfer, Transfer Masuk, Transfer Keluar).
    - Filament v5 Resource: WalletResource & CategoryResource.
    - Validasi scoped-unique terhadap tenant dan soft-delete.
    - Pest Tests: CRUD Dompet & Kategori, validasi duplikasi per-tenant.

- Milestone 3: Pure Event Ledger & Financial Engine
  * Fokus: Inti pencatatan keuangan, integritas mutasi kas riil, dan transfer.
  * Deliverables:
    - Migrasi transfers dan transactions + composite index (account_id, happened_at).
    - Service layer mutasi saldo atomik dengan pessimistic locking (lockForUpdate()).
    - Logika Reversal otomatis pada update/delete transaksi.
    - Transfer antar dompet (auto 2 transaksi ledger + 1 transaksi admin fee jika ada).
    - Perintah Artisan rekonsiliasi saldo: php artisan wallet:reconcile {account_id?}.
    - Filament v5 Resource: TransactionResource & TransferResource.
    - Pest Tests: Race condition prevention, transfer fee deduction, running balance accuracy.

- Milestone 4: Budgets & Debts / Loans Engine
  * Fokus: Manajemen plafon pengeluaran bulanan serta pencatatan hutang/piutang.
  * Deliverables:
    - Migrasi budgets, debts, dan debt_payments.
    - Sinkronisasi instan hutang/piutang ke dompet kas saat pembuatan (initial_transaction_id).
    - Pembayaran cicilan (debt_payments) memotong pokok dan mutasi kas dompet.
    - Validasi anti-overlapping budget bulanan.
    - Filament v5 Resource: BudgetResource & DebtResource.
    - Pest Tests: Integrasi hutang ke kas, pelunasan bertahap, dan perhitungan progress.

- Milestone 5: Analytics, Dashboard Widgets & Performance Optimization
  * Fokus: Visualisasi keuangan real-time dan optimasi kecepatan tinggi.
  * Deliverables:
    - Dashboard stats overview via single consolidated raw SQL query.
    - Widget grafik arus kas bulanan & pie chart kategori (Apex Charts).
    - Widget monitoring plafon anggaran & pengingat jatuh tempo hutang.
    - Integrasi Relation::enforceMorphMap dan optimasi query.
    - Audit query 0 N+1 menggunakan Laravel Debugbar.
    - Konfigurasi mobile-bottom-nav (responsive mobile bottom navigation bar).

- Milestone 6: Member Invitation & Granular Role Authorization
  * Fokus: Kolaborasi keluarga/tim dan perlindungan hak akses berbasis peran.
  * Deliverables:
    - Alur klaim undangan member via token unik (/invitations/{token}).
    - Notifikasi email undangan member.
    - Laravel Policies untuk seluruh Filament Resource berdasarkan AccountRole:
      * owner : Akses penuh.
      * member: CRUD transaksi & operasional penuh, tanpa izin kelola tenant.
      * viewer: Read-only, seluruh action form/edit dinonaktifkan.
    - Pest Tests: Penegakan otorisasi role di seluruh UI Filament.


9. PANDUAN MEMULAI & EKSEKUSI PENGEMBANGAN (HOW TO GET STARTED)
--------------------------------------------------------------------------------
Untuk melanjutkan pengembangan proyek dari status saat ini, ikuti alur kerja baku berikut:

1. Status Proyek Saat Ini:
   - Fondasi Laravel 13, Filament v5, Breezy Auth, dan Pest telah dikonfigurasi.
   - Dokumen perancangan arsitektur lengkap tersedia di:
     docs/superpowers/specs/2026-10-07-dompetkita-core-architecture-design.md
   - Rencana implementasi teknis detail untuk Milestone 1 tersedia di:
     docs/superpowers/plans/2026-10-07-milestone-1-multi-tenancy-foundation.md

2. Cara Memulai / Melanjutkan Milestone:
   - Berikan instruksi langsung ke AI Assistant: "Lanjut Milestone 1" atau "Mulai Task 1".
   - Pengerjaan dieksekusi secara berurutan dari Task 1 hingga Task 5 pada Milestone 1:
     * Task 1: Enums Keanggotaan (AccountRole & MemberStatus) dengan Filament Contracts.
     * Task 2: Migrasi Database Tenancy (accounts & account_member) + AccountFactory.
     * Task 3: Model Eloquent & Relasi Tenant (Account & User).
     * Task 4: Halaman Registrasi Tenant Filament v5 (RegisterAccount) & AppPanelProvider.
     * Task 5: End-to-End Tenancy Isolation & Route Guard Tests.

3. Siklus Standar Pengerjaan per Task (Disiplin TDD):
   a. Red Stage   : Tulis test unit/feature Pest terlebih dahulu di folder tests/.
   b. Verify Fail : Jalankan test untuk memastikan test gagal sesuai ekspektasi:
                    php artisan test --compact --filter=NamaTest
   c. Green Stage : Tulis kode implementasi seminimal mungkin hingga test berhasil.
   d. Verify Pass : Jalankan kembali test Pest untuk memastikan seluruh asersi lulus.
   e. Code Format : Jalankan linter otomatis Laravel Pint:
                    vendor/bin/pint --dirty --format agent
   f. Git Commit  : Lakukan commit per-task dengan format konvensional (feat, test, fix, refactor).

4. Transisi ke Milestone Selanjutnya:
   - Setelah seluruh test pada Milestone 1 lulus 100% (verifikasi via php artisan test --compact),
     buat dokumen rencana implementasi (docs/superpowers/plans/...) untuk Milestone 2.
   - Ulangi siklus TDD yang sama untuk menjaga integritas kode dan bebas regresi.
